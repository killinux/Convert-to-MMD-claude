Convert-to-MMD IK 修复开发日志

记录 XPS→PMX 转换插件中 IK 和 D 骨系统的修复过程、踩坑经历和最终方案。

一、问题背景

Convert-to-MMD 插件将 XPS 模型转换为 PMX 格式，涉及 7 个步骤。其中 Step 5（权重分配）和 Step 6（IK 设置）之间存在一个核心矛盾：

核心矛盾

Step 5 把腿部主骨（左足/左ひざ/左足首）的顶点权重清空，全部转移到 D 骨（足D.L/ひざD.L/足首D.L）上。

Step 6 的 IK 约束驱动的是主骨。

结果：IK 动了主骨，但网格不跟（因为权重在 D 骨上，D 骨没有跟随主骨的机制）。

三、修复过程（时间线）

Phase 1：修复 6 个基础 Bug

全部修复，Step 1-5 跑通。

  • BUG-01/02/03：删除多线程，改为单线程循环 + FINISHED
  • BUG-04：删除 draw_error_menu 中的 obj.select_set(True)
  • BUG-05：edit_bones["xxx"] 改为 .get() 安全访问，缺失时跳过
  • BUG-06：try/finally 保护修改器清理

Phase 2：尝试 COPY_ROTATION + LOCAL

给 D 骨添加 COPY_ROTATION 约束，从主骨复制旋转。

结果：移动 IK 时腿的方向反了

原因：同时发现 3 个层级问题 ——

  • 足D.L 和 左足 的 parent 是 下半身（应为 腰キャンセル.L）
  • 腰キャンセル.L 在 Step 4 才创建，Step 2/3 时不存在
  • 足IK親 的 parent 是 全ての親（应为 None）

Phase 3：修复骨骼层级

对比 PMX 参考模型，修正父子关系：

  • 腰キャンセル.L/.R 提前到 Step 2 创建
  • 左足/右足 parent 改为 腰キャンセル.L/.R
  • 足D.L parent 链经过 腰キャンセル（已有逻辑，但之前因 Step 4 太晚而 fallback 到下半身）
  • 足IK親 parent 改为 None

Phase 4：尝试 COPY_TRANSFORMS + LOCAL

把 D 骨约束从 COPY_ROTATION 改为 COPY_TRANSFORMS（同时复制位置+旋转+缩放）。

结果：方向对了，但截图看变化不明显

Phase 5：尝试 COPY_TRANSFORMS + POSE

改为 POSE 空间。位置数据验证正确（D 骨和主骨坐标一致）。

结果：腿部顶点跑到上半身

原因：COPY_TRANSFORMS 在 POSE 空间下复制了位置偏移，D 骨（很短）被拉到了主骨（很长）的位置。

Phase 6：尝试 COPY_ROTATION + POSE

改回 COPY_ROTATION 但用 POSE 空间。

结果：整条腿翻转上去

原因：D 骨朝向（+Z 朝上）和主骨朝向（-Z 朝下）相反。POSE 空间的旋转复制会导致翻转。

Phase 7：尝试让 D 骨朝向和主骨一致

修改 D 骨创建逻辑，tail 沿主骨方向。

对比 PMX 参考后发现：PMX 标准的 D 骨就是朝上的（+Z），和主骨方向相反是正确的。

方向不是问题，问题在约束方式

Phase 8：分析 PMX 参考的 shadow/dummy 机制

深入分析 PMX 参考模型，发现 D 骨使用三层间接传递而非直接约束：

_dummy_足D.L  (parent=足.L)          ← 挂在主骨下，自然跟随
      ↓ COPY_TRANSFORMS
_shadow_足D.L (parent=腰キャンセル.L)  ← 复制 dummy 的完整变换
      ↓ TRANSFORM (rotation 1:1, LOCAL)
足D.L         (parent=腰キャンセル.L)  ← 读取 shadow 的旋转

这套机制通过两个中间骨骼绕开了朝向不一致的问题。

Phase 9：实现 shadow/dummy 三层机制

在 Step 6 (ik_operator.py) 中实现完整的 shadow/dummy 骨骼创建和约束设置。

结果：IK 抬腿 ✅、左右移动 ✅、网格正确跟随 ✅

4.2 D 骨约束机制

主骨（左足）   ← IK 驱动旋转
    ↓
_dummy_足D.L   parent=左足（跟随主骨自然变换）
    ↓ COPY_TRANSFORMS
_shadow_足D.L  parent=腰キャンセル.L（和 D 骨同父）
    ↓ TRANSFORM (rotation→rotation 1:1, LOCAL)
足D.L          parent=腰キャンセル.L（有顶点权重，驱动网格）

腰キャンセル.L:
  _dummy_腰キャンセル.L  parent=腰
  _shadow_腰キャンセル.L parent=グルーブ, COPY_TRANSFORMS←dummy
  腰キャンセル.L         TRANSFORM←shadow（旋转反转，抵消下半身）

为什么需要三层：

  • 直接 COPY_ROTATION (LOCAL) — D 骨朝上、主骨朝下，局部坐标系不同，旋转复制方向错误
  • 直接 COPY_ROTATION (POSE) — rest pose 不同导致翻转
  • 直接 COPY_TRANSFORMS — 会复制位置偏移，顶点被拉走
  • shadow/dummy 三层 — dummy 挂在主骨下自然继承变换，shadow 用 COPY_TRANSFORMS 获取世界变换，D 骨通过 TRANSFORM 只读取旋转分量。绕开了所有坐标系问题

五、踩坑总结

教训 1：先对比参考模型再动手

一开始凭直觉加 COPY_ROTATION，试了 4 种组合都失败。最后仔细对比 PMX 参考模型的每个骨骼、每个约束，才发现正确方案是三层 shadow/dummy 机制。先读懂目标格式的完整结构，再实现。

教训 2：D 骨朝向相反是 PMX 标准

D 骨朝上（+Z）而主骨朝下（-Z）看起来像 bug，但这是 PMX 格式的设计。不要"修复"标准行为。

教训 3：Blender 约束的空间模式很重要

同一个约束类型，LOCAL / POSE / WORLD 三种空间下行为完全不同。当骨骼的 rest pose 朝向不同时，简单的旋转复制在任何空间下都不正确。

教训 4：逐步执行，确认每步成功

把所有步骤塞在一个命令里，Step 2 超时但没有报错，后续步骤在错误状态上继续执行，导致腰キャンセル 缺失、D 骨 parent 错误。分步执行并验证每步结果。
